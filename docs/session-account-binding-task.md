# 聊天账号绑定体验修复

## 行为定义

- 聊天账号是服务端会话绑定，不是本地偏好。当前会话没有 `credentialID` 时显示“未绑定”；查询失败显示“读取失败”；协议无此能力时明确要求升级；绑定请求未获确认时保留之前的服务端绑定并解释失败原因。
- 账号列表以单选控件表示本聊天绑定。保存期间禁用重复操作并显示“保存中”；只在服务端返回并回读相同 ID 后将新账号显示为已生效。
- 输入框旁的摘要同时展示聊天绑定账号和模型；有执行中的任务时分别说明当前任务账号、下次发送账号，只有可验证的服务端信息才可称为已确认。
- 需要先取得对正式 4096 实例的有效只读认证，核对版本、会话 GET credential 字段、账号列表及 session PATCH 行为；认证失败不作为“不支持”的证据，也不做正式绑定修改。

## 回归验收

区分文本回复结束（会话 idle、无工具）、推理文本结束但工具仍运行（session busy、tool running，停止入口保留）、被调用进程仍运行（工具状态和 server active 均保持 running），以及断线无法查询（明确状态待确认，重连后重新核对）。账号绑定覆盖支持、协议不支持、账号读取失败、绑定拒绝/无回读确认、同聊天换账号和换模型；任何未确认选择都不得显示为已生效。

## 当前实现与验收记录

- V2 适配器从会话 GET 的 `credentialID` 读取绑定；成功会话响应中 `credentialID` 缺失或为 null 表示未绑定，不代表协议不支持。401/403 为认证失败，其他非成功响应（包括会话 404）为读取失败；只将绑定专用 GET/PATCH `/api/session/:id` 的明确 405 视为该方法不支持。界面诊断显示请求方法、路径和状态码，不包含认证头。PATCH 后再次 GET，只有账号一致才由 provider 更新会话缓存；拒绝或未确认时尝试恢复此前读到的绑定。如果无法确认恢复，界面显示绑定未知，不能把新账号标记为已生效。
- 聊天模型面板的单选状态仅对应服务端回读的本聊天账号；保存中禁用再次选择。输入框旁显示账号与模型；已提交且仍在运行的任务显示其提交时的账号和模型，后续选择单独显示为“下次发送”。没有任务账号证据时明确提示未确认。
- fake V2 自检覆盖绑定拒绝、无回读确认、协议拒绝及读取失败；Vitest 验证真实适配器发出的 PATCH/GET 请求。浏览器流程覆盖同聊天换账号和模型、运行中区分、失败后保留原绑定；新增 fake-server 和 E2E 代码仍需独立人工审查，云端 E2E 尚未执行。
- 2026-10-14 运行时链路核对：连接页和 Chat 都从同一 `OpencodeProvider` 的 `useConnection()` 读取 settings、connection 与 `serverCapabilities`；账号动作来自同一 provider 的 `useCapabilities()`。`connectionScope` 用于缓存隔离，不是协议探测 ID。Contract 为 provider 单一状态；连接未成功前能力现为“未检查”，不再将初始 V1 默认值当成协议证据；只有已连接且解析为 V1 才显示不支持。会话 GET 请求使用同一个 scoped V2 client 和活动 project directory。没有从 release App 安全取得本次请求的真实路径/状态码，所以正式端点结果仍未确认；代码路径现将认证/读取失败作为带方法、会话路径、状态码的 UI 诊断，不记录认证资料。
