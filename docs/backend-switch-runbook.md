## 切换门槛与步骤

1. 取得人工代码审查、精确提交的云端全部门禁和同 SHA 签名 APK 的验收结论；明确真实账号请求费用和唯一的服务管理／自启动方式，预留维护窗口。
2. 使用原服务的认证上下文读取 `/api/session/active`，检查 inbox、工具、shell、PTY 和其他客户端；等待任务完成。不得擅自取消正在运行的任务。
3. 记录旧二进制 SHA、HOME/XDG/PATH、端口和启动进程；备份旧可执行文件及配置。用 SQLite `.backup` 在线备份正式库并核验 `PRAGMA integrity_check=ok`；备份目录 0700，机密文件 0600，绝不在聊天或仓库公布凭据。
4. 经维护窗口授权后正常停止**核对过的**旧进程；再次做停机后 SQLite 最终快照、哈希和完整性检查，保留 WAL/SHM 取证；任何时刻只有一个服务访问正式库。复用原认证配置及 HOME/XDG/PATH 启动已验签的新服务监听 4096。
5. 核验 `/api/info`、会话与账号绑定、阻塞表单、标准 PTY WebSocket 和回连；只有明确同意收费范围才做真实账号短请求。确认连接与输入法，记录切换时间、版本、快照位置和检查结果。

## 回退

阻止新请求，等待或经操作者明确选择处理中任务的处理方式；正常停止新服务并确认退出。优先验证备份旧二进制能否读取新库；兼容才复用。若不兼容，先归档新库及 WAL/SHM 并确认两服务均已退出，再从核验过 SHA 与 integrity_check 的**最终停机快照**恢复；不重放不匹配的 WAL。恢复快照会丢失切换后的事务，必须先取得授权。使用原环境启动旧服务，检查 4096、会话、PTY 与 App 连接；不能双实例同时访问数据库。
